Deepfake Network Lab

Future Security Networks: Deepfakes, Network Vulnerabilities, and Defense

What this app is

A set of live simulations that show one idea from our Computer Networks project: a network can carry a deepfake perfectly, so network health cannot prove a video is real. Trust has to be added on top, through process controls, cryptographic provenance and zero-trust design.

Everything runs in your browser. There is no server, no tracking and no external library.

1. Network lab

Move packet loss, jitter and latency on a live RTP/UDP call. See that a fake on a perfect network looks healthy, and a real video on a bad network looks glitchy.

2. Fraud replay (₹)

Replay the Arup deepfake fraud, or a hypothetical Mumbai case, in rupees. Switch controls on and see what breaks the chain.

3. Layer explorer

Click each TCP/IP layer to see where deepfakes interact, which defenses apply, and the common myth.

4. Provenance

Real digital signing (ECDSA P-256) in your browser. Sign a caption, alter one character, and watch verification fail.

5. Zero trust

Toggle identity, device and provenance signals and see the access decision. Network location is ignored.

6. References

The sources behind the project, with the same numbering as our slides.

Key points to remember

StatementWhy
A network carrying a deepfake is not compromised.Packets are delivered normally; the attack is on trust.
HTTPS/TLS does not prove media is authentic.It protects the channel, not the content.
Network anomalies cannot prove a video is fake.Compression, loss concealment and rendering cause glitches too.
A valid signature does not prove the events are true.It proves a key signed the file, not the honesty of the holder.
Broad cybercrime totals are not deepfake losses.FBI totals cover all internet crime or all AI-referencing complaints.

Honest limits of this model

These are simplified simulations built to teach a concept, not real network traffic or a real detector. The Arup figures come from CNN reporting (HK$200 million, about US$25.6 million, 15 transactions). Rupee amounts are converted at an approximate, editable exchange rate. The Mumbai scenario is hypothetical.

Where deepfakes sit in the network stack

Click a layer.

Sign media, then try to tamper with it

Uses your browser’s real Web Crypto API (ECDSA P-256, SHA-256). This is the same idea as C2PA Content Credentials: a signed manifest bound to the media.

What to notice: change even one character and verification fails. But “Sign a false caption” shows a valid signature on a lie: a signature proves which key signed, not that the content is true. Missing provenance means unknown, not fake.

Evaluate an access request

A policy decision point weighs signals for each request. Where the request comes from on the network does not count.
